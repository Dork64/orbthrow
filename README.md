# Orbthrow

FFA-кастомка Dota 2 на 32 героя. Снимок установленной сборки: 2026-11-28 15:28 МСК.

## Структура

- `content/` — исходные ресурсы, запускатели и проект разработки `_project`.
- `game/` — установленная игровая сборка, включая карту и скомпилированные ресурсы.
- `tools/install.ps1` — установка с резервной копией и проверкой хешей.

Кэши редактора, логи, зависимости, промежуточные сборки и резервные копии исключены.
`content/_kv` и `content/_project/data/kv` содержат справочные снимки KV; актуальные значения сверять с установленной Dota 2.
Карта сохранена как готовый VPK: для изменения геометрии нужен исходник карты из Hammer, если он хранится отдельно.

## Получение

Нужны Git с Git LFS, Node.js с npm, LuaJIT в PATH и установленная Dota 2 с Workshop Tools.
Установка зависимостей ниже обращается в сеть; выполняйте её самостоятельно после согласования скачиваний.

```powershell
git lfs install
git clone <URL-репозитория> orbthrow
cd orbthrow
git lfs pull
cd content\_project
npm.cmd ci
npm.cmd run check
```

`check` выполняет сборку, Vitest и LuaJIT. Проверка в Dota 2 проводится отдельно по `content/_project/TESTING.md`.
Для LuaJIT добавьте каталог с `luajit.exe` в PATH текущего терминала.

## Установка в Dota 2

Закройте редактор и игру. Из корня репозитория:

```powershell
# Установить сохранённую готовую сборку:
.\tools\install.ps1 -DotaRoot 'E:\SteamLibrary\steamapps\common\dota 2 beta'
# После изменений и успешного npm.cmd run check установить новую сборку:
.\tools\install.ps1 -DotaRoot 'E:\SteamLibrary\steamapps\common\dota 2 beta' -FromBuild
```

Предварительный просмотр: добавьте `-WhatIf`. Скрипт не удаляет лишние файлы в игре, сохраняет предыдущую версию в `work/` и с `-FromBuild` компилирует Panorama.
Исходники редактируйте в репозитории `content/_project`, затем снова проверяйте и устанавливайте.
Для быстрой проверки с ботами запустите `content/launch_orbthrow.bat`. Для проверки в обычном клиенте используйте `content/launch_like_online.bat`. Оба запускателя находят установленную Доту автоматически. Проверьте путь в `open_tools.bat` и `compile_panorama.bat`, если пользуетесь ими отдельно. Workshop публикует пользователь.

## Работа с Git

```powershell
git status
git add .
git commit -m "Описание изменения"
git push
```

Не редактируйте генерируемые `orbdata.ts` и `fxdata.ts` вручную. Баланс и сферы описаны в `content/_project/docs/BALANCE.md` и `docs/HERO_ORBS.md` относительно проекта.
Папка `game/` хранит снимок: после установки новой сборки обновите её из установленной игры и `content/panorama` из установленной content-папки, без кэшей. `git status` покажет изменения перед коммитом.
Не добавляйте пароли, токены, личные конфиги и файлы самой Dota 2. Бинарные ресурсы, перечисленные в `.gitattributes`, хранятся через Git LFS.

## Первый push на GitHub

Создайте пустой приватный репозиторий без автоматически созданного README. Из корня этой папки:

```powershell
git remote add origin <URL-репозитория>
git push -u origin main
```

Перед открытием публичного доступа проверьте права на распространяемые ресурсы. Лицензия проекту автоматически не назначена.

## Как дорабатывать

Основная рабочая папка — `content/_project`. Открывайте её в редакторе кода.

| Что меняем | Где искать относительно `_project` |
| --- | --- |
| Числа, описания и наборы сфер | `data/orbs/` |
| Исполнение эффектов сфер | `src/vscripts/lib/fxengine.ts`, `src/vscripts/lib/fxmodifier.ts` |
| Общие бонусы сфер и их пределы | `src/vscripts/modifiers/modifier_orb_controller.ts` |
| Серверные правила режима | `src/vscripts/` |
| Интерфейс и карточки | `src/panorama/`, `content/panorama/` |
| Автотесты | `tests/` |
| Генерация, сборка и симуляции | `tools/` |

Перед изменением прочитайте `TESTING.md`; для баланса — `docs/BALANCE.md` и `docs/HERO_ORBS.md`.
Сферы всех героев можно посмотреть в `content/_project/docs/orbs-wiki.html`. После изменений данных обновите страницу командой `npm.cmd run wiki` из `content/_project`.
`orbdata.ts` и `fxdata.ts` генерируются из данных: меняйте первоисточник, затем запускайте сборку.
Не правьте только готовые Lua в `game/scripts/vscripts`: следующая сборка их перезапишет.

Обычный цикл работы:

1. Создайте ветку из корня репозитория: `git switch -c fix/описание`.
2. Измените нужные исходники в `content/_project`.
3. В этой папке выполните `npm.cmd run check`. Команда собирает код и запускает Vitest и LuaJIT. Не ставьте новые зависимости без согласования скачивания.
4. Из корня репозитория выполните `tools/install.ps1 -DotaRoot 'путь к dota 2 beta' -FromBuild`. Скрипт сохранит резервную копию и установит результат; Доту он не запускает.
5. Пользователь запускает Доту и проверяет нужные пункты `TESTING.md`. Успешные автотесты не означают, что эффект проверен в клиенте.
6. Обновите описание изменения и инструкции проверки. Если нужен актуальный готовый снимок, перенесите установленный `game/dota_addons/orbthrow` в `game/`, а установленный `content/dota_addons/orbthrow/panorama` в `content/panorama/`. Исходный `_project` при этом берите из репозитория, не заменяйте старой установленной копией.
7. Проверьте `git diff` и `git status`, затем сделайте коммит и `git push`. Workshop публикует пользователь отдельно.

Если меняете баланс, сначала изучите штатную способность, таланты, Scepter/Shard и контрмеры по актуальным KV установленной Доты. Сравните базовую способность, способность со сферой, с предметом/зачарованием и с их сочетанием. Проверьте взаимодействие со стороны противника.

Из известных правил: сопротивление эффектам именно от сфер ограничено 50%, базовая перезарядка BKB — 50 секунд, дополнительные заряды должны восстанавливаться по одному. Историю и остальные условия проверяйте по документации проекта.

Для передачи задачи другому разработчику укажите: желаемое поведение, героя/сферу, шаги воспроизведения, номер сборки и отдельно результаты автотестов и проверки в клиенте. Пути к вашей Steam-библиотеке могут отличаться.
